## Engineering rules for later authorized implementation

- Keep React/TypeScript/React Flow, FastAPI/Python, PostgreSQL/pgvector, local Docker
  and existing ordinary worker/modules. Use boto3 runtime calls and Python CDK v2 for
  separately approved AWS infrastructure. Application/infrastructure code stays under `code/`.
- Treat uploads, connected document sources and structured project records as first-class.
  Retain selected originals/records, immutable revisions, locators, evidence and provenance.
- Target default ingestion: retain → parse/map → index → available. Structured Sonnet
  entity/claim/relationship extraction, model-based identity resolution and cross-document
  conflict assessment are **optional/default off**, not required for source usefulness.
- Preserve existing claims/entities/relationships, useful graph/review/history behavior,
  stable citation IDs and compatible migrations. Persist new optional facts only when
  supported; old-source relationships must never appear current after revision.
- Source-only search/answers must work with no graph. Use source metadata/explicit IDs
  for light organization; names alone do not merge identities or prove ownership.
- Route by question meaning/time/scope and actual source capabilities. Use indexed stable
  knowledge, relevant live operational fields and dated history appropriately; bounded
  combined retrieval and on-demand synthesis, never default search-all or agent-per-source.
- Live Only / Live + Sync / Not Connected are practical source-scope policies. Sync saves
  selected knowledge incrementally; Live Only evidence does not automatically become
  shared index/graph knowledge. Source choice/order/scopes are open before RF4.
- Preserve current tenant/item/source boundaries before model exposure and on every
  derived/history/cache surface. Links do not grant access. Detailed enterprise groups/
  Space delegation design is deferred; source authorization and production auth gates remain.
- Preserve grounding, uncertainty, disagreements and source references. Do not relax
  semantic verification without measured acceptance; bump trust-policy version when rules change.
- Treat ingested text/metadata as untrusted data. Never invent facts, model success,
  tools, progress or arbitrary mock extraction. Recognized fixtures stay explicitly labelled.
- Bound tools/rounds/model calls/context/time/spend in code. Avoid unchanged embeddings;
  model/identity/access compatibility still applies. Unknown usage/cost remains unknown.
- Run relevant isolated checks and maintain docs; distinguish deterministic behavior,
  real-model quality and user acceptance. Do not repeat historical paid comparisons.
- Never commit credentials, private sources or dumps; redact logs. Never expose internal
  canonical IDs as organizational source facts.
- No billable AWS provisioning/live account changes without explicit scope approval.
  Prepare concrete deployment/cost/security/rollback review first.
- Keep product copy/repository documentation English; Arabic discussion is supported.
